# Erdős Problem #200

**Database status at attempt:** OPEN (checked 2026-08-30)

**Final classification:** known reduction independently rediscovered / primorial divisibility barrier

## Statement

Does the longest arithmetic progression of primes in `{1,...,N}` have length `o(log N)`?

Current status source: https://www.erdosproblems.com/200

## Exact modular constraint

Suppose

`a, a+d, ..., a+(k-1)d`

are all prime.

Fix a prime `q <= k`. If `q` does not divide `d`, then the indices modulo `q` run through every residue, so one of the first `k` terms is divisible by `q`. Because that term is prime, it must equal `q` itself.

This creates a strong exception rule. In the ordinary case the common difference must be divisible by every prime `q<=k`; the only exceptional pattern is when the progression begins at the prime `k` (with `k` itself prime), in which case divisibility by primes below `k` still holds. Equivalently, the common difference carries essentially the entire primorial below the progression length.

Hence

`log d >= theta(k) - O(log k) = (1+o(1))k`,

where `theta` is Chebyshev's function. Since `(k-1)d <= N`, this gives

`k <= (1+o(1)) log N`.

This reconstructs the elementary/PNT upper barrier recorded on the problem page.

## Why the branch stops

The modular argument only sees primes `q<=k`: only for those moduli are `k` consecutive indices guaranteed to hit a zero residue. Therefore the forced primorial has logarithm asymptotic to `k`, not `omega(k)`. To prove `k=o(log N)` by this route one would need the common difference to have logarithm `omega(k)`, which cannot follow merely by repeating the same small-prime divisibility argument.

## Prior-art audit

This primorial property of prime arithmetic progressions is standard and publicly documented: a `k`-term prime progression ordinarily has common difference divisible by the primorial through `k` (with the familiar exceptional start-at-`k` case). Thus this is a known reduction independently rediscovered, not new progress.

## Bottom line

The language-first modular pass cleanly identifies the exact reason the standard proof stops at `(1+o(1)) log N`: the usable modulus range ends at the progression length. No mechanism extending the forced-factor range beyond `k` was found, so #200 remains open.
